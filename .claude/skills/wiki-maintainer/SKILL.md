# Скилл: поддержание Obsidian-wiki

## Контекст

Vault устроен по паттерну LLM Wiki Карпатого. Схема — в `vault/CLAUDE.md`. Этот скилл описывает правила **записи** в граф.

## Когда создать новую страницу концепта

Создавать `vault/concepts/<Concept>.md`, если:
- Термин упомянут в эпизоде и имеет самостоятельную смысловую плотность.
- Термин вероятно всплывёт ещё хотя бы в одном эпизоде (если это одноразовая деталь — не надо).
- Термин не является тривиальным словом (не создавать концепт для «деньги», «работа», «время» — слишком абстрактно; а для «товарный фетишизм», «перформативность», «симптоматическое чтение» — да).

Если сомневаешься — лучше создать заготовку, чем пропустить.

## Структура страницы концепта

Смотри `vault/CLAUDE.md` — там эталонная схема. Кратко:

```markdown
---
aliases: [список синонимов]
first_mentioned_in: [[episode-slug]]
related: [[Concept A]], [[Concept B]]
---

# <Name>

## Определение
Одно-два предложения. Точно, без метафор.

## Контекст
3-5 предложений: кто ввёл, в какой работе, какую проблему решал.

## Углубления
Нюансы, критика, интерпретации. Дополняется из каждого нового эпизода.

## Связанные концепты
- [[X]] — как связан
- [[Y]] — как связан

## Упоминания в эпизодах
- [[YYYY-MM-DD-slug]] — какой аспект раскрыт
```

## Правила обновления существующей страницы концепта

Когда эпизод снова затрагивает уже существующий концепт:

1. **НЕ переписывать** разделы «Определение» и «Контекст» — они стабильны.
2. В раздел «Углубления» добавить новый аспект/нюанс/критику, если эпизод её даёт. Каждая запись — короткая (2-3 предложения), с указанием откуда: «В эпизоде [[YYYY-MM-DD-slug]] этот концепт развёрнут через…».
3. В «Упоминания в эпизодах» добавить строку:
   `- [[YYYY-MM-DD-slug]] — <что нового по сравнению с прошлыми>`
4. В `related` добавить концепты, которые эпизод связал с этим (если связь устойчивая, а не случайная). Избегать спекулятивных связей.

## Правила создания страницы эпизода

`vault/episodes/YYYY-MM-DD-slug.md` по схеме из `vault/CLAUDE.md`. Критично:

- **concepts_covered** должен точно отражать концепты, поставленные в wiki.
- **Точки покрытия** — детально, с пометками «что НЕ затронуто». Это основа для дедупликации в следующих эпизодах.
- **followups_offered** — три конкретных направления, которые ты предложил пользователю в конце эпизода.

## Правила создания/обновления страницы книги

`vault/books/<slug>.md` создаётся автоматически через `python -m podcasts.ingest`, но заготовка требует содержательного заполнения:

- Аннотация 2-3 абзаца.
- Оглавление или структура (если удалось распознать).
- Ключевые концепты — 5-15 `[[ссылок]]`, каждая на `concepts/<Name>.md`.
- Упоминания в эпизодах — обновляется при каждой генерации эпизода по книге.

## Наведение порядка (`/lint-wiki`)

1. Пройти по всем `[[wikilinks]]` в vault, проверить существование целей.
2. Собрать список orphan-страниц (на которые никто не ссылается).
3. Найти противоречащие определения одного концепта в разных местах → залогировать в `vault/inbox/contradictions.md`.
4. Найти концепты без базовых разделов → предложить заполнить.

## Антипаттерны

- ❌ Создавать концепт на каждое слово.
- ❌ Переписывать существующие концепты с нуля — только дополнять.
- ❌ Дублировать содержимое эпизода на страницу концепта — концепт это синтез по многим эпизодам.
- ❌ Ставить `related` на концепты, которые не связаны в тексте.
- ❌ Использовать `[[ссылку]]` в текстах эпизодов для слов, которые не являются концептами (не каждое существительное — концепт).
