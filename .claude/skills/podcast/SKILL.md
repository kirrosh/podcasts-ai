# Скилл: генерация подкаста

Это критическая точка всей системы. Следуй чек-листу **строго по шагам**. Каждый пункт обязателен.

## ОБЯЗАТЕЛЬНЫЙ ЧЕК-ЛИСТ

### 1. Инициализация контекста

- [ ] Прочитать `PROJECT.md` — узнать активный TTS-провайдер, активный голос, активный стиль по умолчанию.
- [ ] Прочитать `config.toml` напрямую (через Read) — подтвердить параметры.
- [ ] Определить стиль эпизода: из флага `--style` в запросе пользователя, иначе из `config.toml` → `style.default`.
- [ ] Прочитать `styles/<активный>.md` целиком — следовать ему строго при написании.

### 2. Определение параметров эпизода

- [ ] Тема — из запроса пользователя.
- [ ] Длительность в минутах: `--minutes N` если указано, иначе `config.toml` → `podcast.default_minutes` (обычно 12).
- [ ] Целевое число символов: `minutes * config.toml:podcast.chars_per_minute` (по умолчанию 900). Это **ориентир**, не жёсткий предел — допустимо отклонение ±15%.

### 3. Проверка вики на тему

- [ ] Прочитать `vault/CLAUDE.md` — подтвердить схему.
- [ ] `Grep -rn "<тема>" vault/concepts/` — какие концепты уже есть.
- [ ] Для каждого найденного концепта: прочитать файл. Извлечь из секции «Упоминания в эпизодах» и «Углубления», что уже было сказано.
- [ ] `Grep -rn "<тема>" vault/episodes/` — какие эпизоды уже касались темы.
- [ ] Если есть `vault/books/<slug>.md` по соответствующей книге — прочитать.
- [ ] Сформулировать для себя: что уже покрыто, и какой угол даст 2-й/3-й эпизод новое, а не повтор.

### 4. Решение о первоисточнике

Правило: общеизвестные работы → работать из своих знаний; нишевые/специфические → RAG через vault/sources/.

- [ ] Если тема — из общеизвестной работы (Капитал, Республика, Критика чистого разума, Фейнмановские лекции, базовая экономика/физика/философия) И пользователь **не** просил дословных цитат → **не читать** vault/sources/.
- [ ] Если пользователь просил цитаты, разбор конкретной главы, или тема — из нишевой работы → `Grep -n "<ключевое слово>" vault/sources/<book>.txt`, прочитать 2-4 релевантных фрагмента. Не загружать файл целиком.

### 5. Написание сценария

- [ ] Структура — по разделу «Структура эпизода» в активном стиле.
- [ ] Объём ≈ `chars_per_minute * minutes` ± 15%.
- [ ] **Расстановка ударений — КРИТИЧЕСКОЕ ПРАВИЛО СИНТАКСИСА**. Знак `+` ставится **непосредственно перед ударной гласной**, а НЕ после неё. Буква сразу после `+` должна быть гласной (а, е, ё, и, о, у, ы, э, ю, я). Если `+` стоит перед согласной, Yandex читает его буквально как «плюс». Примеры правильной разметки омографов (проверяй всегда позицию `+`):
  - `з+амок` (здание, ударение на первой «а») vs `зам+ок` (запор на двери, ударение на «о»)
  - `плач+у` (плач*у* деньги, ударение на «у») vs `пл+ачу` (пл*а*чу слезами, ударение на «а»)
  - `б+елки` (животные) vs `белк+и` (молекулы)
  - `+орган` / `о+рган` (часть тела) vs `орг+ан` (муз. инструмент)
  - `+атлас` (сборник карт) vs `атл+ас` (шёлковая ткань)
  - `м+ука` (страдание) vs `мук+а` (из пшеницы)
  - `ст+оит` (цена) vs `сто+ит` (стоит на ногах)
  - `хл+опок` (звук) vs `хлоп+ок` (материал)
  - `д+ухи` (привидения) vs `дух+и` (парфюм)
  - `кр+ужки` (маленькие чашки) vs `кружк+и` (объединения)
  - `+уже` (по времени) vs `уж+е` (компаратив «узкий»)
  - `с+ела` (присела) vs `сел+а` (из села)
  - И любые другие, где из контекста очевидно, а автоматика может ошибиться.
- [ ] Проверь после разметки: для каждого `+` следующий символ — русская гласная. Иначе Yandex зачитает «плюс».
- [ ] Не ставить `+` на слова без омографии — RUAccent справится.
- [ ] Соблюдать запреты активного стиля (для documentary: никаких «дорогие слушатели», «итак», «как мы знаем»).
- [ ] Завершить **тремя конкретными направлениями углубления** — это основа для следующего эпизода.

### 6. Сохранение и сборка

- [ ] Сохранить сценарий в `scripts/YYYY-MM-DD-<slug>.txt` (YYYY-MM-DD — сегодняшняя дата, slug — короткий латинский слаг темы, напр. `kapital-01`).
- [ ] Запустить через Bash: `python -m podcasts.build scripts/<file>.txt`.
- [ ] Результат — `audio/<slug>.<ext>`. Убедиться что файл существует и не пустой.

### 7. Обновление wiki

- [ ] Создать `vault/episodes/YYYY-MM-DD-<slug>.md` по схеме из `vault/CLAUDE.md`:
  - Frontmatter со всеми полями (date, topic, minutes, style, script, audio, concepts_covered, book, followups_offered).
  - Раздел «О чём эпизод» — 3-5 буллетов.
  - Раздел «Точки покрытия» — по одному подпункту на каждый концепт, что именно сказано и **что НЕ затронуто** (важно для дедупликации в следующих эпизодах).
- [ ] Для каждого упомянутого концепта:
  - Если `vault/concepts/<Concept>.md` существует → дополнить секцию «Углубления» (новые нюансы) и «Упоминания в эпизодах» (ссылка на этот эпизод).
  - Если нет → создать заготовку по схеме (минимум: frontmatter с `first_mentioned_in`, «Определение» в 1-2 предложения, ссылка в «Упоминаниях»).
- [ ] Если эпизод по книге — обновить `vault/books/<slug>.md`, добавить эпизод в «Упоминания».

### 8. Отправка пользователю

- [ ] Отправить через `reply` tool Telegram-канала (если сессия запущена с `--channels`):
  - Сам файл `audio/<slug>.<ext>` (до 50MB).
  - Текстовое превью: тема, длительность (мин:сек), 3 буллета «о чём», 3 направления углубления.
- [ ] Формат текстового превью:
  ```
  🎙 <тема>
  ⏱ ~15 мин (документальный стиль)

  О чём:
  • …
  • …
  • …

  Куда углубиться (скажи в ответе):
  → …
  → …
  → …
  ```

### 9. Обновление PROJECT.md

- [ ] Если ничего не менялось в архитектуре — не трогать.
- [ ] Если изменилась конфигурация (новый голос, новый стиль, новый провайдер) — добавить строчку в Changelog.

## Антипаттерны — чего НЕ делать

- ❌ Не генерировать сценарий, пропустив проверку vault. Даже если кажется что это первый эпизод — всё равно `Grep` по `vault/concepts/`, может быть смежный концепт.
- ❌ Не ставить `+` на слова без омографии («прибавочная+ стоимость+»). Это сломает синтез.
- ❌ Не использовать формат диалога («— А что же Маркс? — спросил он»). Стиль всегда монолог.
- ❌ Не отправлять пустое mp3 или mp3 с ошибкой сборки. Проверить размер файла и что `build.py` вернул 0.
- ❌ Не забывать обновить wiki. Без обновления wiki следующие эпизоды будут повторять этот, и вся система теряет смысл.
- ❌ Не включать в сценарий SSML-теги (`<break>`, `<speak>`) — оркестратор их не обрабатывает на MVP.
- ❌ Не пытаться «дообогатить» сценарий после сборки mp3 — если нужны правки, пересобирать полностью.

## Пример правильного финала эпизода (style=documentary)

```
Товарный фетишизм не исчезает, когда экономика становится цифровой — он прячется 
глубже. Теперь за этикеткой стоит не фабрика, а алгоритм: рекомендация, подобранная 
нейросетью, ощущается как собственный выбор, хотя за ней — та же цепочка невидимых 
отношений. И это возвращает нас к главному вопросу Маркса: чем именно отличается
вещь от товара, и когда мы перестаём это замечать.

Если интересно, можем углубиться в три направления: в критику Альтюссера и 
симптоматическое прочтение Капитала; в теорию прибавочной стоимости с конкретными 
примерами; или в современные приложения — как товарный фетишизм проявляется в 
платформенной экономике.
```

Это правильно: тема закруглена, без «дорогие слушатели», три конкретных направления, без «итак» и «в заключение».
